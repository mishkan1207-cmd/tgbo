# tgbo — автопостинг в Telegram-канал

Бот сам придумывает пост на русском языке и публикует его в ваш Telegram-канал.
Работает на GitHub Actions: по расписанию 3 раза в день и вручную.

**Платные сервисы не нужны. API-ключ для ИИ тоже не нужен.**
Основные роутеры работают из России без регистрации и без карты.

## Как устроено

`tgbo.py` перебирает бесплатные роутеры по порядку. Если один недоступен или
упёрся в лимит — автоматически идёт следующий. Пост всё равно выйдет.

| # | Роутер | Ключ | Проверено |
| - | - | - | - |
| 1 | **LLM7.io** | не нужен | отвечает, понимает русский, лимит сообщает сам |
| 2 | **Pollinations** | не нужен | отвечает, хороший русский текст |
| 3 | OrcaRouter | `ORCA_API_KEY` | только как резерв, если ключу разрешены модели |
| 4 | Google Gemini | `GEMINI_API_KEY` | необязательно; консоль недоступна из РФ |

Провайдеры 3 и 4 подключаются **только если** соответствующий ключ задан.
Без ключей бот работает на первых двух.

### Почему не OrcaRouter

Изначально бот использовал `orcarouter/free` и падал с ошибкой **HTTP 403**.
Причины, обе подтверждены на практике:

1. Роутер `orcarouter/free` отдаёт `403 free_quota_exhausted`, когда нет
   свободной бесплатной модели, и требует привязать «зрелый» GitHub-аккаунт
   (`err_free_access_denied`).
2. Вход в консоль OrcaRouter через GitHub отдаёт **403** — управлять ключом
   невозможно.
3. Ключ `ORCA_API_KEY` отвечает `403 model_access_denied` (`block_key_scope`)
   на **все** модели: `GET /v1/models` с этим ключом возвращает пустой список.

Поэтому OrcaRouter оставлен лишь необязательным резервом.

## Что в репозитории

| Файл | Назначение |
| --- | --- |
| `tgbo.py` | Генерация и публикация. Только стандартная библиотека Python |
| `.github/workflows/autopost.yml` | Расписание, ручной запуск, проверки |
| `tests/test_tgbo.py` | 54 теста логики. Без сети, в Telegram не пишут |
| `check_key.py` | Проверка, какие модели отвечают вашим ключом |
| `state/posted.json` | История постов. Появляется после первой публикации |

## Какие Secrets нужны

**Settings → Secrets and variables → Actions → New repository secret**

| Secret | Обязателен | Значение |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | **да** | токен бота от @BotFather |
| `CHANNEL_ID` | **да** | `@username` канала или `-1001234567890` |
| `ORCA_API_KEY` | нет | можно оставить как есть, используется только как резерв |
| `GEMINI_API_KEY` | нет | если когда-нибудь появится ключ Google |

Больше ничего не требуется — ключей ИИ для основной работы не нужно.

## Порядок первого запуска

1. **Actions → Telegram AI Autopost → Run workflow**
2. Поставьте `dry_run` = **true** и нажмите Run — текст сгенерируется и попадёт
   в лог, но в канал ничего не отправится.
3. Убедитесь, что в логе есть готовый пост и строка
   `DRY_RUN=1 — в Telegram ничего не отправлено`.
4. Хотите проверить отправку, не трогая канал: напишите боту в личку `/start`,
   узнайте свой id и запустите workflow с `test_chat_id` = этот id.
   Пост придёт вам в личку.
5. Когда всё устраивает — запустите workflow с `dry_run` = false.
   Дальше бот будет публиковать сам по расписанию.

## Расписание

Cron в GitHub Actions работает **в UTC**, часового пояса у него нет.
Сейчас настроено на московское время:

| МСК | UTC | cron |
| --- | --- | --- |
| 06:00 | 03:00 | `0 3,9,15 * * *` |
| 12:00 | 09:00 | |
| 18:00 | 15:00 | |

Для другого пояса: `UTC-час = местный час − смещение от UTC`.
Например UTC+5 и 09:00 / 15:00 / 21:00 → `cron: "0 4,10,16 * * *"`.

GitHub может задержать запуск из очереди на 5–30 минут — это нормально.

> GitHub отключает `schedule` в репозитории, где 60 дней не было активности.
> Достаточно любого коммита, чтобы включить снова.

## Ручной запуск: параметры

| Параметр | Что делает |
| --- | --- |
| `dry_run` | Сгенерировать текст, но не отправлять в Telegram |
| `test_chat_id` | Отправить в этот чат вместо канала |
| `force` | Опубликовать, даже если пост похож на недавний |
| `custom_prompt` | Пожелание к теме, например «про космос» |

Можно задать переменную репозитория (**Variables**, не Secret):

| Variable | Назначение |
| --- | --- |
| `AI_MODEL` | Своя модель LLM7, например `GLM-5.3-Flash` |

## Если что-то не работает

**`Не заданы Secrets: ...`** — добавьте перечисленные Secrets.

**`LLM7: ни одна модель не ответила`** — чаще всего это рейт-лимит. Бот сам
ждёт столько, сколько просит API (оно присылает `Retry after N seconds`),
и переключается на Pollinations. При 3 постах в день это редкость.

**`Не удалось получить доступ к CHANNEL_ID`** — бот не администратор канала
или `CHANNEL_ID` неверен. Добавьте бота в администраторы канала.

**`Telegram API отказал (400): chat not found`** — для числового id нужен
префикс `-100`. Проще указать `@username` публичного канала.

**`Не удалось сохранить историю постов`** — включите
**Settings → Actions → General → Workflow permissions → Read and write**.
Пост при этом уже опубликован, не работает только защита от дублей.

## Проверка на своей машине

```bash
python -m py_compile tgbo.py
python tests/test_tgbo.py          # 54 теста, сеть не нужна
python check_key.py orca           # проверить права ключа OrcaRouter
```

Реальный прогон без публикации:

```bash
DRY_RUN=1 python tgbo.py            # Linux/macOS
$env:DRY_RUN="1"; python tgbo.py    # Windows PowerShell
```

## Безопасность

- Ключи читаются только из переменных окружения (`os.getenv`), в коде их нет.
- Ключ Gemini передаётся заголовком, а не в URL — он не попадает в логи.
- Пост отправляется без `parse_mode`, чтобы спецсимволы не ломали отправку.
- Текст из полей ручного запуска сначала попадает в переменные окружения и
  только потом используется в оболочке.
- Тест `test_no_hardcoded_secrets_in_source` падает, если в коде появится
  что-то похожее на реальный ключ.
