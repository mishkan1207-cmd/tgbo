# tgbo — автопостинг в Telegram-канал

Бот сам придумывает пост на русском языке через бесплатный ИИ-API и публикует
его в ваш Telegram-канал. Работает на GitHub Actions: по расписанию 3 раза в
день и вручную. Ни VDS, ни платных подписок, ни платных API не требуется.

## Что в репозитории

| Файл | Назначение |
| --- | --- |
| `tgbo.py` | Генерация поста и публикация. Только стандартная библиотека Python |
| `.github/workflows/autopost.yml` | Расписание, ручной запуск, проверки, публикация |
| `tests/test_tgbo.py` | Тесты логики. Сеть не используют, в Telegram не пишут |
| `state/posted.json` | История постов. Создаётся автоматически после первой публикации |

## Какие Secrets нужны

Откройте: **Settings → Secrets and variables → Actions → New repository secret**.

| Secret | Обязателен | Где взять |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | да | У вас уже есть (от @BotFather) |
| `CHANNEL_ID` | да | `@username` канала или числовой id вида `-1001234567890` |
| `GEMINI_API_KEY` | да | https://aistudio.google.com/apikey — бесплатно, без карты |
| `ORCA_API_KEY` | нет | Можно оставить как есть. Используется только как резерв |

Дополнительно можно задать переменную репозитория (**Variables**, не Secret):

| Variable | Назначение |
| --- | --- |
| `AI_MODEL` | Своя модель вместо списка по умолчанию, например `gemini-3.5-flash-lite` |

Никогда не вставляйте ключи в код, в коммиты или в сообщения чата — только в Secrets.

## Порядок первого запуска

1. Создайте бесплатный ключ на https://aistudio.google.com/apikey
   (вход по обычному Google-аккаунту; оплата и банковская карта не нужны).
2. Добавьте `GEMINI_API_KEY` в Secrets репозитория.
3. Загрузите в репозиторий `tgbo.py`, `.github/workflows/autopost.yml`
   и папку `tests`.
4. **Actions → Telegram AI Autopost → Run workflow**
   - `dry_run` = **true** → нажмите Run.
   - Это безопасная проверка: текст сгенерируется и попадёт в лог, но в канал
     ничего не отправится. В логе будет видно, какая модель ответила.
5. Убедитесь, что в логе есть готовый текст поста и строка
   `DRY_RUN=1 — в Telegram ничего не отправлено`.
6. Если хотите проверить отправку, не трогая канал: создайте приватный
   Telegram-чат, узнайте его id, и запустите workflow с
   `test_chat_id` = этот id. Пост уйдёт туда, а не в канал.
7. Когда всё устраивает — запустите workflow без параметров (`dry_run` = false).
   Пост опубликуется в канал. Дальше он будет публиковаться сам по расписанию.

## Расписание

Расписание в GitHub Actions задаётся **в UTC**, часового пояса у cron нет.
Сейчас настроено на московское время:

| МСК | UTC | Значение в cron |
| --- | --- | --- |
| 06:00 | 03:00 | `0 3,9,15 * * *` |
| 12:00 | 09:00 | |
| 18:00 | 15:00 | |

Для другого часового пояса: `UTC-час = местный час − смещение от UTC`.
Например для UTC+5 и времени 09:00 / 15:00 / 21:00 → `cron: "0 4,10,16 * * *"`.

GitHub может задержать запуск из очереди на 5–30 минут. Для бесплатного
планировщика это нормально и не является ошибкой.

## Ручной запуск: параметры

| Параметр | Что делает |
| --- | --- |
| `dry_run` | Сгенерировать текст, но не отправлять в Telegram |
| `test_chat_id` | Отправить в этот чат вместо канала (безопасная проверка) |
| `force` | Опубликовать, даже если пост похож на недавний |
| `custom_prompt` | Пожелание к теме, например «про космос» |

## Если что-то не работает

**`Не заданы Secrets: ...`** — добавьте перечисленные Secrets и запустите снова.

**`Gemini: все модели не сработали`** — в тексте ошибки будет точная причина.
Частые случаи:

- `HTTP 400 ... API key not valid` — ключ скопирован с ошибкой или от другого проекта.
- `HTTP 403` — у ключа нет доступа к модели. Задайте `AI_MODEL` с другой моделью,
  список доступных смотрите на https://ai.google.dev/gemini-api/docs/models
- `HTTP 429` — исчерпан бесплатный лимит на этот день. Запуск по расписанию
  сам повторится; лимиты обновляются в полночь по времени Pacific.

**`Не удалось получить доступ к CHANNEL_ID`** — бот не администратор канала,
либо `CHANNEL_ID` указан неверно. Добавьте бота в администраторы канала.

**`Telegram API отказал (400): chat not found`** — для числового id канала
нужен префикс `-100`. Удобнее указывать `@username` публичного канала.

**Посты не выходят по расписанию** — GitHub отключает `schedule` в репозитории,
где не было активности 60 дней. Достаточно любого коммита, чтобы включить снова.

## Как проверялось

Тесты логики запускаются и локально, и в workflow на каждом запуске:

```bash
python -m py_compile tgbo.py
python tests/test_tgbo.py
```

Тесты не обращаются к сети: они проверяют очистку ответа модели от markdown и
служебных фраз, проверку длины и пустоты, поиск дубликатов, разбор ответа API
и отсутствие ключей в исходном коде.

## Безопасность

- Все ключи читаются только из переменных окружения (`os.getenv`).
- В логи не попадают токены: ключ Gemini передаётся заголовком, а не в URL.
- Пост отправляется без `parse_mode`, чтобы спецсимволы не ломали отправку.
- Пользовательский текст из полей ручного запуска сначала попадает в
  переменные окружения и только потом используется в оболочке.
- `permissions: contents: write` нужен только для коммита `state/posted.json`.
